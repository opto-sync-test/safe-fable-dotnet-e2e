# Async Task borrow checker safety contract — cross-backend v1

**Canonical ownership syntax:** Use `rt borrow value`, `rt mut borrow value`, `rt take value`, `rt copy value`, and `rt share value`. The language contract does not use C/C++ `&` or `*` pointer operators. Backend-internal borrow markers must never be treated as source syntax.

**Status (2026-10-21): normative safety gate, not a claim of cross-backend execution parity.**
Companion to `contracts/v2/CPU_GPU_TASK_V2.md`. Implementations MUST fail closed when any required proof or lowering is absent.

## Boundary and identity

`task { ... }`, `cpu task { ... }` and `gpu task { ... }` submit independent logical work immediately and produce `Future<T>`; `nb { ... }` aliases retain equivalent lifetime checks. Task **submission**, not `await`, is the ownership-transfer boundary. `cpu { ... }` is a synchronous source region, not a new independently-owned child, though an internal continuation handoff remains a suspension barrier. `gpu { ... }` and `gpu task { ... }` require device-fence-backed lifetime accounting. The word `task` remains contextual, never a globally reserved identifier.

Each executable child requires an authenticated compiler admission record tied to the exact checked Program/TaskExpr, parent scope epoch, execution domain, and runtime-created child identity. Re-parsed/untyped ASTs, optimizer clones, foreign handles and user-supplied metadata cannot mint authority. A runtime or backend without this chain rejects before execution/artifact publication.

## Static borrow and capture rules

1. Build a CFG-aware, place-sensitive capture/loan inventory at submission, including transitive captures through closures, nested tasks, `defer`/`finally`, channel callbacks, `select`, and method receivers. Evaluate captures in source order and atomically commit move/loan effects; a rejected spawn leaves the parent ownership state unchanged. Branch joins conservatively merge moved/loaned states; unknown aliases overlap. Capture discovery MUST respect lexical binding introduction and shadowing, including classic `for` initializers, `for-of`, destructuring, pattern/catch/select bindings, and recursive lambda names; a Task-local shadow is not a parent capture, while a binding initializer still captures any outer values it evaluates.
2. Copyable immutable values are snapshotted at submission. Non-Copy captured owners transfer exactly once into the child and require a compiler-derived `Send` proof. The parent, siblings and nested callbacks cannot use the moved binding unless ownership is lawfully returned as an owned result. Capturing a mutable binding is NOT implicit shared memory. `Future<T>` is affine, never Copy: a backend may move it into another Task only when cross-scheduler await/cancellation is runtime-safe and `T` is itself Send-safe; otherwise reject.
3. Ordinary loans created using `rt borrow value` and `rt mut borrow value`, actor-state loans, `MutexGuard`, foreign/raw pointers and untrusted handles are not independently Send-safe captures. Interior mutability by itself is not a blanket rejection: uniquely owned `RefCell<T>`, `Mutex<T>` and `RwLock<T>` may MOVE when the canonical auto-trait rules derive `Send`; `Rc<T>` is non-Send, while `Arc<T>`/`Weak<T>` require the stronger concurrent `Send + Sync` proof from their referent. Forbid unsafe authority escape into ordinary Tasks, returned Futures, channels, FFI, device queues and unstructured detached work. A capability cannot be laundered through an owned nominal class (including inherited/generic fields), structural record/struct, generic wrapper, closure environment, `rt copy`, `rt share`, or serialized representation; Send derivation is transitive and unknown provenance fails closed. `ActorRef<T>` is an explicit Copy/Send mailbox capability: `T` is protocol/target type information, not embedded actor state, so Send derivation must not recurse through `T` as if the actor instance were captured. Recursive nominal Send derivation fails closed without a complete proof over instantiated generic types; reencountering a class declaration is not proof because later substitutions can introduce non-Send values. User-defined types that share a built-in capability's name must not inherit its Send privileges by spelling alone. `ActorRef<T>` requires authenticated actor-target provenance, never an opaque or ordinary class target. Every positive backend MUST derive Task capture eligibility from the same backend-independent `Send`/`Sync`/`Share` lattice used by the language type system: Task ownership transfer requires `Send`, sharing wrappers may additionally require `Sync`, and unresolved generic/opaque provenance fails closed unless an explicit checked bound proves the required trait.
4. Scoped immutable read borrowing is a *separate*, explicitly proven exception: require an active lexical structured TaskScope, exact immutable borrow binding and root allocation identity/generation, whole-region or authenticated disjoint access path, derived `Sync` referent, scope-bound runtime claim and exact scheduler-child retirement. The child may resume on a different carrier only while the claim remains live. An unrelated alias in the same region acquires no permit. Unsupported targets reject even a statically valid scoped-read claim.
5. Scoped mutable WRITE capture remains **rejected** on all executable backends until distinct WRITE authority, disjoint place proofs, reborrow freezing, inter-task conflict control and cancellation fencing are implemented and exercised. Being inside `nb scope` or `critical` alone does not authorize it.
6. Returned `Future<T>` payloads must own, copy or carry an explicitly shareable frozen value. Borrowed references, guards, actor `state` projections and device pointers cannot become ordinary Future results. If an API intentionally returns a scoped view in future, it requires a distinct non-escaping, lifetime-indexed type and an exact join proof; never erase it into an ordinary `Future<T>` carrying a borrowed view.
7. Actor code remains single-flight regardless of carrier migration. A Task is not a second actor turn and never inherits ambient actor `self`/state or supervisor authority. Persistent actor state lives solely in `state { ... }` and is accessed through the verified critical state-loan API; such loans cannot escape into a child Task.

## Suspension, failure and reclamation

- Treat `await`, blocking select/channel I/O, `rt cooperate`, compiler-inserted loop/call safepoints, executor migration, cancellation, exceptional cleanup and CPU↔GPU transitions as possible continuation boundaries. A live loan can cross only with proven pinned/heap-owned storage and an authenticated lifetime authority; otherwise reject. Revalidate exact generation/permit on every resumed child turn.
- Do not retire memory on logical Future completion, timeout or cancellation request. Hold the parent loan and all resource/FFI/device authority until final cleanup AND scheduler-confirmed physical quiescence (or verified never-registration). A GPU command additionally requires its real provider fence. Unknown outcomes poison/pin authority; errors and catch/trap cannot manufacture a successful drain.
- `do task`/dropped handles remain supervised descendants. Scope shutdown seals admission, propagates cancellation, awaits physical child exit and publishes failures without blocking an actor carrier or publishing user callbacks under an ownership lock. Adoption across scopes must be explicit and authorized.
- The parent must not start a conflicting mutable access while a scoped child READ is still live. Multiple readers need same-generation shared region proof; malformed epochs, ABA/stale tickets, duplicate child IDs and partial admission rollbacks fail closed.

Tests must include negative diagnostics and **no generated artifact**, positive scalar controls, parent/child and sibling races, nested captures, callbacks, CFG diamonds/loops, cross-carrier resumption, double moves, first-failure cleanup precedence, cancellation-vs-completion and target-specific pointer/ABI behavior. CI must identify exact source/branch/blob SHA, actual executed compiler and test steps; an unexecuted workflow or source-free model is not production conformance. Never mirror private source to another org without an explicitly approved destination/policy.

## State of implementation

Java/GraalVM has draft executable owned Task and separate scoped READ authority implementations; these are not necessarily merged with the CPU/GPU v2 branch. LLVM has partial native ownership and rejects source Task execution. The Wasm source path depends on the exact pinned LLVM compiler plus artifact admission. .NET currently has an arithmetic/structured-source bootstrap, not general Task ownership lowering. All four must preserve negative gates until an independently tested integration proves this complete contract.
