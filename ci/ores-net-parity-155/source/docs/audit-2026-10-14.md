# Security and correctness audit — 2026-10-14

Scope: draft PR #1, strict Native AOT Windows backend, as of hardening commits on `feat/windows-native-aot-backend`.

## Findings addressed

1. **Incorrect primitive method return signature (high):** Hand-built Cecil `TypeReference("System", "Int64", ..., true)` encodes a general valuetype token rather than the CLI primitive `ELEMENT_TYPE_I8`. The generated method now uses `module.TypeSystem.Int64` after setting a strong-named `System.Runtime` reference. Verification asserts `MetadataType.Int64`, core-library scope and the static entry signature.
2. **Premature expression-depth failure (medium):** Previously, CIL emission recursively walked left-associated arithmetic expressions and rejected valid long flat expressions. The emitter now uses an explicit work stack, node budget, evaluation-stack tracking and final stack-depth validation. Regression coverage includes 2,048 operands and a deliberately excessive evaluation-stack AST.
3. **Ambiguous native artifact checks (high):** Publishing an `.exe` is not sufficient to prove strict Native AOT. `verification/assert-native-pe.ps1` checks PE32+ signature, target machine, absent COM/CLR descriptor, and absent `.runtimeconfig.json` for **both** the compiler and the application. CI rejects an ordinary managed test assembly through the same verifier. The managed generated assembly is a compile-time-only reference, and publishing fails if that DLL is copied into the app's output folder.
4. **Insufficient actor stress coverage (medium):** Added concurrent mailbox send/receive regression checks and retained stale-reference, owned-message copy and queue boundary cases.
5. **AOT analysis warnings (medium):** Publish script now requests MSBuild-wide warnings-as-errors. Native AOT still needs an actual Windows publish to confirm that its entire dependency graph is supported.

## What is NOT demonstrated

- GitHub Actions Windows job execution: recent Windows runs failed with no returned steps or usable logs. This cannot establish compiler build success or failure from a C# diagnostic.
- A Native AOT executable running on Windows x64 or ARM64.
- Formal verification of mailbox linearizability, actor isolation or typed Oreslang semantics.
- A full Oreslang compiler, type system, ownership checks, actor runtime, scheduling, async/await, or hot reload.
- Zero-GC behavior: Native AOT retains the .NET managed GC.

## Release blockers

- [ ] Generate `OresGenerated.dll`, publish a truly native Windows `oreslang-app.exe`, and execute the resulting program with the expected result.
- [ ] Run PE/CLR-header and managed-sidecar checks, unit tests, concurrency stress tests, and review AOT linker/trimming diagnostics.
